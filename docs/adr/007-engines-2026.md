# ADR 007 — Estado da arte 2026: engines de canto/geração para o Caine

- **Status**: Aceito
- **Data**: 2026-09-17
- **Decisores**: lu4nn3ry
- **Relacionado**: ADR 001 (state of the art), ADR 003 (ferramentas de voz),
  ADR 004 (MIDI/SVS), ADR 006 (artistas como cantores), `out/melodia-afinada.mp3`

## Contexto

O ADR 006 definiu as personalidades de `secured/` como artistas que cantam a
melodia afinada, mas o passo 3/3 de render (DiffSinger/OpenUtau) nunca foi
implementado: hoje ele só escreve arquivos de alinhamento (`.ds`/`.uta`), não
gera áudio cantado. Pesquisa web de 2026 para decidir o que instalar/programar
no Caine, considerando a stack atual: **WSL2 (Ubuntu) + GTX 1650 (Turing, 4GB
VRAM) + CUDA** (verificado com `nvidia-smi` 610.43 / CUDA 13.3) e pipelines
existentes de transcrição (Basic Pitch + pyin), alinhamento letra→nota e letras
por persona.

## Estado da arte (pesquisa web 2026)

### 1. SVS "Vocaloid-like" — DiffSinger OpenVPI + `diffsinger-utau`

- **DiffSinger (mantido pelo OpenVPI)** continua o SVS de difusão de referência
  em 2026: 44.1 kHz, acústico via difusão + vocoder (HiFi-GAN / NSF / pc-ddsp),
  controle de pitch/energia/breathiness, samplers de aceleração (DDIM, PNDM,
  DPM-Solver++, UniPC, Rectified Flow) — https://github.com/openvpi/DiffSinger
- Existe CLI headless no PyPI **`diffsinger-utau`** (inferência por linha de
  comando e API Python: duração → pitch → variance → acústico → vocoder,
  compatível com voicebanks do OpenUtau) —
  https://pypi.org/project/diffsinger-utau
- Render no **OpenUtau oficial** usa CPU por padrão (DirectML no Windows para
  GPU dedicada); em **WSL/Linux** `diffsinger-utau` com PyTorch CUDA é a via
  natural — https://github.com/openutau/OpenUtau (wiki DiffSinger support)

### 2. Geração de música completa — ACE-Step v1.5

- Modelo fundação open-source "comercial-grade", **< 4GB VRAM** (temperamento
  para a GTX 1650), < 2 s por música em A100 / < 10 s numa RTX 3090.
- Text-to-music em 50+ idiomas com letra como condição, duração 10 s–10 min,
  **cover de áudio existente**, repaint/edição local, vocal→BGM, layering e
  **LoRA treinável com ~8 músicas** para estilo próprio.
- Veículo local de "Suno": gera faixa completa a partir de
  `melodia-afinada.mp3` + letra da persona — https://github.com/coloth/ccstep

### 3. TTS/clone por persona — CosyVoice2-0.5B / IndexTTS-2

- **CosyVoice2-0.5B** (~4GB, zero-shot clone, cross-lingual/multilíngue) roda
  em GPU modesta e substitui o GPT-SoVITS do ADR 003 (antigo) para a "fala" do
  Caine — https://github.com/FunAudioLLM/CosyVoice
- **IndexTTS-2** lidera a leva 2026 em timbre/clareza/clone zero-shot (MOS alto,
  GPU util baixa ~28%) — arxiv 2502.05512
- Fish Speech S2 **não é opção** aqui: exige ≥ 24GB de VRAM.

### 4. O que NÃO muda

- **Basic Pitch + pyin** (transcrição áudio→MIDI, ADR 004) seguem sendo o
  padrão de fato em 2026 para AMT local (mesma abordagem do `midi_transcribe`).
- **Demucs** (separação de stems) continua atual; **seed-vc** segue como VC
  zero-shot de referência (ADR 003).

### 5. NVIDIA NIM — o que ajuda (pesquisa set/2026)

**Restrição-chave**: os **Speech NIMs 2026** (TTS, ASR, Studio Voice, NMT,
VoiceChat) exigem GPU com **Compute Capability ≥ 8.0 (Ampere+)** e **≥ 16 GB
VRAM**, e o **TTS NIM não tem suporte a WSL2**. A GTX 1650 (Turing 7.5, 4 GB)
**não roda esses microserviços localmente** — a integração é via **API hospedada
do `build.nvidia.com` / NVCF**, que é o mesmo caminho que o `caine-nim` (ADR
002) já usa (curl + API key, codec JSON próprio).

O que agrega ao Caine (via API, plugável como novas tools no NIM):

- **Magpie TTS Multilingual** — síntese com vozes por emoção, **pt-BR incluso**;
  renova o slot de TTS falado do `secured/` (substitui o GPT-SoVITS antigo do
  ADR 003). Endpoints HTTP: `POST /v1/audio/synthesize` (multipart) +
  `GET /v1/audio/list_voices`.
- **Magpie TTS Zeroshot** — clone de voz a partir de **3–10 s** de referência
  (acesso restrito; validação de licença/consentimento antes).
- **Nemotron 3.5 ASR** — transcrição de áudio (40 idiomas, multi-streaming);
  útil para transcrever vocais de referência e realimentar o alinhamento.
- **Nemotron NMT 1.6b** — tradução em 36 idiomas; casa com a **Bubble em 24
  línguas** (letras/intros traduzidas automaticamente).
- **Studio Voice** — aprimoramento de voz (fala gravada com microfone ruim);
  preparação do `out/rg/<id>/voz.wav` antes de usar como referência.
- **LLM NIMs** são o único caso **self-hostável na GTX 1650** (generic config
  aceita CC ≥ 7.0; com 4 GB só modelos quantizados ≤ 4 GB, ex. nemotron
  pequeno) — opcional para reduzir custo de inferência local.

## Decisão

Não muda decisão existente; registra a direção recomendada de instalação/
programação em 2026, em ordem de prioridade:

1. **DiffSinger → render real** (`caine-voice artists sing --engine diffsinger`):
   instalar DiffSinger OpenVPI (ou `pip install diffsinger-utau`) + 1 voicebank
   open (ex. OpenVPI) + vocoder `nsf_hifigan`, e implementar o passo 3/3 de
   `produzir-versao-artista` para `:diffsinger` via CUDA. É o que fecha o
   pedido "cantar a melodia-afinada.mp3 com letra".
2. **ACE-Step v1.5** como novo comando `caine-voice cover`/`make`: gerar faixa
   completa (arrranjo + voz) condicionada pela melodia afinada e pela letra da
   persona; maior salto de capacidade do projeto.
3. **CosyVoice2-0.5B (ou IndexTTS-2)** para renovar o TTS do `secured/` (intro
   falada por persona; clone a partir de `out/rg/<id>/voz.wav`).
4. **NIM via API (não local)** para as capacidades de speech que a GTX 1650 não
   comporta: TTS Magpie pt-BR (voz falada), ASR, NMT (Bubble em 24 línguas) e
   Studio Voice (limpeza do `voz.wav`). Plug como novas tools no `caine-nim`.

Grid de VRAM no alvo (GTX 1650 4GB): DiffSinger lite e ACE-Step cabem;
CosyVoice2-0.5B cabe; Fish Speech S2 **não** (24GB) e MiniMax Music 3 não (~23GB).
Speech NIMs locais **não** (CC ≥ 8.0 + ≥ 16GB; TTS sem WSL2).

## Consequências

**Positivas**

- Fecha o buraco funcional do ADR 006 (render de verdade no WSL/GPU).
- Torch/CUDA já confirmados viáveis no WSL (passthrough do driver Windows).
- Engines headless/CLI encaixam na arquitetura "Lisp orquestra ferramentas
  externas" (ADR 003) sem acoplar o Lisp a GUI.
- Speech do NIM via API reaproveita o `caine-nim` (ADR 002) já pronto
  (curl + API key + codec JSON), sem exigir GPU além da budget.

**Negativas / custos**

- Downloads grandes: DiffSinger + voicebank + vocoder (~1–2GB); ACE-Step
  (~mais alguns GB de pesos); CosyVoice2-0.5B (~2–4GB).
- 4GB de VRAM limitam batch/qualidade: modelos grandes exigem quantização
  (FP16/NF4) e fatiamento; tempo de render pode ser alto em iterações longas.
- Voicebank único para os 4 artistas sacrifica a distinção de timbre; timbre
  por persona exige um voicebank (ou LoRA) por artista.

**Riscos**

- **Licença/uso**: DiffSinger Apache-2.0 (openvpi) e ACE-Step abertos, mas
  voicebanks têm licenças próprias — validar antes de distribuir arte.
- **Ética de clone vocal** (ADR 006): só usar vozes fictícias/consentidas; a
  ficção do Caine (mind files) não autoriza clone de vozes reais. Magpie TTS
  Zeroshot tem acesso restrito e revisão de caso.
- **Pesquisa datada**: mercado de música-IA muda rápido; o ASR 007 é um
  snapshot — manter o log atualizado em novas rodadas de pesquisa.
- **Limite de 4 MB do gRPC offline do TTS NIM** para saídas longas — usar
  streaming para faixas maiores.
